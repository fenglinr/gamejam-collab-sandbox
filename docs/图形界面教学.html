main 和任务分支，到底是什么？

main 是你们共享的已完成版本。任务分支是从它分出来的一条修改路线。你在自己的分支做事，不会立即改变朋友使用的 main。任务完成后，通过拉取请求合回 main，朋友再拉取。

同一时刻，工作副本显示的是当前选中分支的文件。切换前先保存文件，并把当前任务的改动提交好。

我提交了，朋友为什么还看不到？

按顺序检查：① 你有没有点“发布分支 / 推送”？② 任务是否已合入 main？③ 朋友当前是否选中 main，并点了“获取更新 → 拉取”？

提交只保存在本地；推送会上传；合并会更新 main；拉取才把远端 main 带到朋友的电脑。

朋友合并在先，我的分支落后了怎么办？

工作区干净时，先切到 main，获取更新并拉取；再切回自己的任务分支。选择“分支 → 合并到当前分支…”（Branch → Merge into current branch…），选 main，把新内容合入自己的任务线。

检查结果后推送，再回到拉取请求。若出现冲突，先按下面的冲突说明处理，不要盲目选择覆盖。

出现冲突，是不是把项目弄坏了？

冲突说明两项修改需要你们决定如何组合。先停在当前任务分支，记下有冲突的文件。普通文本可以逐段决定保留内容；不知道应该留哪一版时，请对方一起判断。

Blender 文件等二进制资产不能像文本一样拼起来。Godot 场景即使是文本格式，处理后也要在引擎中打开检查。第一轮不同文件练习完成后，再有意练习一次文本冲突。

模型、图片、音频怎么交接？

这个仓库已经为常见二进制资产配置了 Git LFS。正常提交和推送时，GitHub Desktop 会交接这些文件；你不用把素材单独上传到另一个网站。

先在文件夹中查看下载的 game/assets/audio/test-tone.wav。它应当是一段可播放的短音频，而不是只有几行文字。大文件每次改动都会累积存储用量，练习阶段保持素材很小。

为什么不在这一课里修改音频或模型？

练习仓库的音频和部分源文件设为可锁定资产。GitHub Desktop 当前没有原生的 LFS 锁定按钮，所以第一次先练文本，音频只验证能否下载、播放。

真正修改同一个模型前，要先落实取锁与解锁的入口，并遵守同一文件由一人暂时负责的约定。这一步仍需单独配置和双账号实测；不要把只读限制强行绕开。
